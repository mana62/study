# コンピューティング

## コンピューティングとは？
- アプリケーションを動かすための「計算リソース」を提供するサービス群
- AWS では用途に応じて **仮想サーバー / サーバーレス / コンテナ / VPS** など複数の選択肢がある

## 主要コンピューティングサービス
### Amazon EC2

**特徴**
- OS・ミドルウェアを自由に構築できる
- スケール、ネットワーク、セキュリティを細かく制御可能
- 企業システム〜大規模アプリまで幅広く対応

### AWS Lambda
- **サーバーレスでコードだけ実行するサービス**

**特徴**
- サーバー管理不要（サーバーレス）
- イベント駆動（API、S3、DynamoDB、EventBridge など）
- 自動スケーリング
- 実行時間＋リクエスト数で課金（従量課金）

**Lambda の構成要素**
- 関数コード
- ランタイム（Node.js, Python, Go など）
- レイヤー（共通ライブラリ）
- 環境変数

**メリット**
- 運用負荷削減（サーバー管理なし、監視・ログは自動）
- コスト最適化（毎月100万リクエスト無料）
- 高可用性（マルチAZ、99.99%）
- 開発スピード向上（デプロイが速い）

**よくある組み合わせ**
- **API Gateway → Lambda → DynamoDB**
- ※セットではないが、サーバーレス構成として相性抜群

## Amazon Lightsail
- **AWS版の超かんたんVPS（仮想サーバー）サービス**

**特徴**
- EC2より圧倒的に簡単
- WordPress や LAMP を数クリックで起動
- 固定月額で料金がわかりやすい
- 小規模サイト・個人ブログ向け

**向いている用途**
- 初心者の AWS 入門
- 小規模サイト、テスト環境
- EC2 は難しいけど VPS を使いたい

## Amazon ECS
- **Docker コンテナを管理・運用するためのサービス**

**特徴**
- コンテナアプリケーションを簡単にデプロイ・スケール
- **EC2 または Fargate を実行基盤として選択可能**
- **JSON形式のタスク定義**で構成を管理
- 自動スケーリング対応

**コンテナ構成の全体像**
- レジストリ：**Amazon ECR**（**イメージ保管**）
- コントロールプレーン：Amazon ECS / Amazon EKS
- データプレーン：Amazon Fargate / EC2

**Amazon EKS とは？**
- **EKS は Kubernetes のコントロールプレーン（管理部分）を AWS が全自動で運用してくれる**

**ECS と EKS の違い**
| 項目 | ECS | EKS |
|------|------|------|
| 管理方式 | AWS独自 | Kubernetes標準 |
| 学習コスト | 低い | 高い（K8s知識必須） |
| 柔軟性 | 中 | 非常に高い |
| 向いてる人 | AWSだけで完結したい | K8sを使いたい・マルチクラウド |


**使う場面**
- マイクロサービス
- コンテナ化されたアプリの運用
- スケールする API / バッチ処理

## まとめ
| サービス | 一言でいうと | 特徴 | 向いている用途 |
|---------|--------------|------|----------------|
| EC2 | 仮想サーバー | 自由度高い、細かい設定可能 | 大規模・企業システム |
| Lambda | サーバーレス実行 | イベント駆動、自動スケール、従量課金 | API、バッチ、軽量処理 |
| Lightsail | 超かんたんVPS | 固定月額、初心者向け | 小規模サイト、WordPress |
| ECS | コンテナ管理 | Docker運用、Fargate対応 | マイクロサービス、API |
