# AWS 設計②
**Well-Architected Framework**
- AWSで推奨される設計
- 下記６つの設計原則

1. **信頼性：障害などによる停止を軽減**

信頼性の主要サービス
- 基盤：IAM/BPC/Auto Scaling/ELB/Cloud Formation
- 変更管理：Cloud Tail/AWS Config
- 障害管理：Cloud Watch


2. **パフォーマンス効率**

パフォーマンス効率の主要サービス
- コンピューティング：Auto Scaling/Lambda
- ストレージ：EBS/S3/Glacier/EFS
- データベース：RDS/Dynmo DB/Elastic search/Aurora/Redshift
- 容量と時間のトレードオフ：Cloud Front/Elasti Cache

3. **安全性**

セキュリティ
- データ保護：ELB/EBS/S3/RDS/KMS
- 権限管理：IAM/MAF
- インフラ保護：VPC
- 検出制御：Cloud Tail/Cloud Watch/AWS GuardDuty/Amazon Inspector

4. **コスト最適化**

コストの主要サービス
- 需要と供給の一致：Auto Scaling
- コスト効率化の高いリソース：EC2購入方式/Trusted Advisor
- 支払いの認識：Cloud Watch/見積もりツール
- 継続した最適化：AWS最新情報/Trusted Advisor

5. **運用場の優秀性**

運用場の優秀性の主要サービス
- 準備：Cloud Formation/Codeシリーズ/Runbook Playbook
- 運用：System Manager/Servise Catalog/CloudTrail/AWS Artyfact/AWS GuardDuty
- 進化：継続的かつ段階的な改善のために時間とリソースを割り当て、運用の有効性と効率性を向上させる

6. **接続可能性**

- AWSの主な対応：インフラに関するエネルギー使用率を80パーセント削減
- ユーザー側の対応：クラウドを利用した効率的なアプリケーション設計やサービス選択を実施

サステイナビリティの設計原則（環境への影響を減らすこと ）
1. 影響の理解：ワークロードの環境負荷を測定する
2. 目標設定：長期的なサステナビリティ目標を設定
3. 利用率最大化：過剰プロビジョニングを避ける
4. マネージドサービス活用：共有インフラで効率化
5. データ効率化：不要データ削除・圧縮
6. 効率的なHW/SW採用：環境負荷を減らすために、より省エネで効率の良いハードウェアやソフトウェアを選ぶ

HW = Hardware（ハードウェア）
SW = Software（ソフトウェア）

AWSのサステイナビリティツール
- Well-Architected Tool
→ サステナビリティ設計をチェックするツール

- Customer Carbon Footprint Tool
→ AWS利用によるCO₂排出量を見える化

- Compute Optimizer
→ 過剰スペックを検出して省エネ提案

- Cost Explorer
→ コスト削減＝リソース削減につながる分析ツール


３つの仕組みで構成されている

1. ホワイトペーパー：６つの原則のドキュメントが用意されてる
2. AWSのSAまたは認定パートナーによる支援制度：AWSのスタッフが支援
3. 説不チェック向けのWell-Architected Tool：AWSのtoolを使うことで、確認
