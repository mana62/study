# AWS責任共有
- AWSでは、**クラウドそのものの安全はAWSが担当**し、**クラウドの中で何をどう使うかは利用者が担当**

つまり、
- AWS = 建物・設備の管理人
- 利用者 = その建物を使う会社
というイメージ

## ① AWS側の責任（Security OF the Cloud）
AWSが守る部分： **クラウド基盤そのものの安全管理**

具体例：
- データセンター建物の警備
- サーバー機器の管理
- ネットワーク機器の保護
- ハードウェア故障対応
- AWSサービスの可用性維持
- 仮想化基盤の保護

## ② 利用者側の責任（Security IN the Cloud）
**AWS上で利用者が設定・運用する部分**

具体例：
- IAMユーザー・権限設計
- パスワード管理
- MFA設定
- EC2のOS設定
- ミドルウェア設定
- セキュリティグループ設定
- 不要サービス停止
- データ暗号化
- バックアップ取得
- アプリの脆弱性対策

## 一緒にやる責任（共有統制）
**AWSだけでも利用者だけでもなく、協力して行う部分**

具体例：
- パッチ適用（一部AWS、一部利用者）
- ネットワーク設定
- モニタリング
- インシデント対応
- ログ管理

## 責任共有モデルの3つの統制
### 1. 継承される統制
- AWSが対応してくれて、利用者はその恩恵を受けるもの

例：
- データセンター警備
- 電源管理
- 物理サーバー保守
→ 利用者は気にしなくていい

### 2. 共有統制
- AWSと利用者の両方が関わるもの

例：
- OSパッチ
- 設定監視
- ネットワーク対策

### 3. ユーザー固有統制
- 完全に利用者が責任を持つもの

例：
- IAM権限設計
- パスワード管理
- データ暗号化設定
- アプリ脆弱性対策
- バックアップ方針
AWSは基盤を守る
利用者は設定とデータを守る
