# CloudWatch
**AWS上のサーバー・アプリ・ログ・インフラをまとめて監視するサービス**

AWS環境の健康診断ツール + 異常通知システム + グラフ表示ツール

例えば：
- EC2のCPUが90%超えた
- サーバーのメモリ不足
- アプリでエラー発生
- ログイン失敗が急増
- 夜間にサーバーダウン
こうした状態を自動で検知できる


## 機能概要
### ① CloudWatch メトリクス
#### メトリクスとは？
- **数値データによる監視情報**

例：
- CPU使用率
- ネットワーク通信量
- ディスクIO
- リクエスト数
- エラー件数

AWSサービスは自動でメトリクスを送ってくれる

代表例（EC2）
| メトリクス             | 意味         |
| ----------------- | ---------- |
| CPUUtilization    | CPU使用率     |
| NetworkIn         | 受信通信量      |
| NetworkOut        | 送信通信量      |
| DiskReadOps       | ディスク読み込み回数 |
| StatusCheckFailed | インスタンス障害   |


CPU監視例
- 20%以下 → 余裕あり
- 50%前後 → 通常
- 80%以上 → 負荷高い
- 95%以上継続 → 危険
- メモリ監視は注意

EC2標準ではメモリ使用率は取得されない
👉 取得するには：Amazon CloudWatch Agent をEC2へインストール

すると：
- メモリ使用率
- swap使用量
- ディスク使用率
- プロセス監視
まで可能

### ② CloudWatch Logs
#### Logsとは？
- **サーバーやアプリのログファイルを集約保存する機能**

例えば：
- nginx access.log
- error.log
- Apacheログ
- アプリケーションログ
- Laravelログ
- Node.jsログ
- OS syslog
をAWSへ送れる

**メリット**
- 複数台サーバーのログを一箇所管理
- 10台EC2があっても全部まとめて検索可能


### ③ CloudWatch アラーム
#### アラームとは？
- **メトリクスが一定条件を超えたら通知する機能**

例
- CPU高負荷通知

条件：
- CPU使用率 > 80%
- 5分継続
→ メール通知


通常は **Amazon Simple Notification Service (SNS)** を使う

送信先：
- メール
- Slack連携
- Lambda起動
- 自動復旧処理
- 実務では超重要

監視していても通知されなければ意味がない
**CloudWatch + Alarm + SNS が基本構成**

### ④ CloudWatch ダッシュボード
#### ダッシュボードとは？
- **監視状況をグラフ画面で見える化する機能**

画面例
- WebサーバーCPU
- DBサーバーCPU
- メモリ使用率
- アクセス数
- エラー件数
- レスポンスタイム
を1画面に表示で切る

**メリット**
- 障害時すぐ状況確認
