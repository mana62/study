# IAM（Identity and Access Management）
AMSリソースへの認証と認可を安全に実施するための仕組み

AWSで、
- 誰が（Identity）
- 何に（Resource）
- どこまで操作できるか（Access）
を**管理する**仕組み

### リソースとは
AWSでいう「リソース」は、**AWS上の各種サービスや作成した対象物**

代表例：
- EC2インスタンス
- S3バケット
- RDSデータベース
- Lambda関数
- DynamoDBテーブル
- VPC
- IAMロール（これも対象になることあり）

## IAMでできること（主な機能）
### ① AWSアカウント内のID作成・管理
- ユーザーを作る

例：
- 田中さん用アカウント
- 開発チーム用権限
- システム連携用アカウント

### ② リソースへのアクセス権限管理
- 誰が何できるか決める

例：
- AさんはS3閲覧のみ
- BさんはEC2起動可能
- 開発チームはRDS変更不可

### ③ 一時的な権限付与
- 必要な時だけ権限を与える

例：
- 1時間だけ管理者権限
- EC2からS3へアクセスさせる
（IAMロールで実現）

## IAM基本構成（超重要）
### 1. IAMユーザー
- 人間用アカウント

例：
- 社員A
- 管理者B

**ログインIDとパスワードを持つ**

### 2. IAMグループ
- ユーザーをまとめる箱

例：
- 開発部グループ
- 管理者グループ

**ユーザーごとに設定せず、まとめて権限付与できる**

### 3. IAMロール
IAMロールとは、**一時的に権限を貸し出す仕組み**

例：
- EC2がS3アクセスする
- LambdaがDynamoDB更新する
- 他AWSアカウントからアクセスする

## IAMポリシー
- **権限ルールを書いた設定ファイル**
- JSON形式で記述

例：
```json
{
 "Effect":"Allow",
 "Action":"s3:GetObject",
 "Resource":"arn:aws:s3:::test-bucket/*"
}
```
意味：test-bucket のファイル閲覧を許可

## IAMポリシーの構成要素
### Version
- ポリシー文法バージョン

### Statement
- 権限ルール本体

### Effect
- Allow（許可）
- Deny（拒否）
※明示的Deny最優先

### Action
- 何をできるか

例：
- s3:GetObject
- ec2:StartInstances

### Resource
- 対象リソース

例：
- 特定S3バケット
- 全EC2

### Condition
- 条件付き許可

例：
- IP制限
- 時間帯制限
- MFA必須

## IAMユーザーの種類
### ① ルートユーザー
- **AWSアカウント作成時の最強アカウント**

- 全権限
- 請求情報変更可能
- 削除可能
👉 普段使わない

### ② 管理者
- **管理用IAMユーザー**

- IAM管理
- リソース作成
- 運用全般

### ③ パワーユーザー
- **強めの一般ユーザー**

- 多くの操作可能
- IAM管理は不可が多い

## IAMの専用用語
### アイデンティティ（Identity）
- **認証される存在**

例：
- IAMユーザー
- IAMロール

### エンティティ（Entity）
- **IAM内の実体**

- ユーザー
- グループ
- ロール

### プリンシパル（Principal）
- **操作を行う主体**

例：
- IAMユーザー田中
- EC2ロール
- 他アカウント
「誰がアクセスしてきたか」

### リソース
- **操作対象**

例：
- S3
- EC2
- RDS

### フェデレーティッドユーザー
- **外部認証連携ユーザー**

例：
- Googleログイン
- 社内ADログイン
- Azure ADログイン
AWSにIAMユーザー作らずログインできる

## AWS Organization
- **複数AWSアカウントをまとめて管理する仕組み**

イメージ：
会社全体で
- 開発アカウント
- 本番アカウント
- 検証アカウント
- 経理アカウント
を一括管理

## AWS Organization主な機能
### 管理機能
- 複数アカウント一元管理
- SCPで権限制御
- OU（組織単位）で整理

### 運用・コスト
- 請求一本化
- RI/Savings Plans共有
- コスト集計
