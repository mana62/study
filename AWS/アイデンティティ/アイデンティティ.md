# AWS アイデンティティ & アクセス管理
AWS の**アイデンティティ領域は大きく分けて 5カテゴリ** に整理できる：
- IAM（AWSリソースへのアクセス管理）
- アカウント管理（複数アカウント統制）
- ユーザー認証（アプリのログイン機能）
- 一時的認証情報（STS）
- オンプレ連携（AD / フェデレーション）

# IAM（Identity and Access Management）
## AWS IAM
**AWSリソースへのアクセス権限を管理するサービス**

### できること
- IAMユーザー / IAMロール / IAMポリシー
- 最小権限の付与
- サービスごとのアクセス制御

### 使う場面
- AWSリソースにアクセスする人・アプリの権限管理

## IAM Identity Center（旧AWS SSO）
**AWS環境とアプリへのシングルサインオン（SSO）を提供**

### 特徴
- **複数AWSアカウントへのログインを一元管理**
- Okta / Azure AD など外部IdPとも連携
- **IAMユーザーを作らずにアクセス管理できる**

# AWS Organizations（複数アカウント管理）
## AWS Organizations
**複数のAWSアカウントを一元管理するサービス**

### 特徴
- アカウントの階層管理（OU）
- SCP（サービスコントロールポリシー）で制限
- 請求統合（Consolidated Billing）

### 使う場面
- 企業で複数アカウントを安全に管理したいとき

# Directory Service（AD連携）
## AWS Directory Service
**Active Directory（AD）をAWSで利用するためのサービス**

### 種類
- AWS Managed Microsoft AD：フルマネージドAD
- AD Connector：オンプレADをそのまま使う
- Simple AD：軽量AD

### 使う場面
- Windowsサーバーの認証
- オンプレADとAWSの統合

# Cognito（アプリのユーザー認証）
## Amazon Cognito
**アプリにログイン機能を追加できるサービス**

### 2つのプール
- **ユーザープール**：ユーザー管理（メール/パスワード、SNSログイン）
- **IDプール**：A**WSリソースにアクセスするための一時認証情報を発行**

### 使う場面
- Web/モバイルアプリのログイン機能
- 認証基盤を自前で作りたくないとき

# STS（Security Token Service）
## AWS STS
**一時的な認証情報（トークン）を発行**するサービス

### 特徴
- 有効期限つきの一時クレデンシャル
- クロスアカウントアクセス
- Cognito や IAMロールと組み合わせて利用

# Secrets Manager
## AWS Secrets Manager
**パスワード・APIキーなどの機密情報を安全に管理**

### 特徴
- 自動ローテーション
- 暗号化
- アプリから安全に取得可能

# フェデレーション認証（オンプレ連携）
## フェデレーション（Federation）
**オンプレADや外部IdPのユーザーが、IAMユーザーを作らずにAWSへログインできる仕組み**

例：
- 社員が会社のADアカウントでAWSにログイン
- SAML / OIDC で連携

## まとめ
| サービス | 役割 | 主な用途 |
|----------|------|-----------|
| IAM | AWSリソースの権限管理 | ユーザー/ロール/ポリシー管理 |
| IAM Identity Center | SSO | 複数アカウントのログイン統合 |
| Organizations | 複数アカウント管理 | OU/SCP/請求統合 |
| Directory Service | AD連携 | Windows認証、オンプレAD統合 |
| Cognito | アプリ認証 | ユーザープール/IDプール |
| STS | 一時認証情報 | クロスアカウント、短期トークン |
| Secrets Manager | 機密情報管理 | パスワード/APIキーの安全管理 |
| フェデレーション | 外部IdP連携 | AD/Okta/AzureADでAWSログイン |
