# コスト最適化

## AWSコスト最適化とは？
- **AWS Well-Architected Framework**でも重要テーマで、**必要な性能を維持しながら、ムダなコストを減らすこと**

## 1. 無料利用枠（Free Tier）
- AWSには**3種類**ある

### ① Always Free（常時無料）
- 期限なしで無料

例：
- AWS Lambda 一定回数まで無料
- Amazon DynamoDB 少量無料
- Amazon CloudWatch 一部無料

### ② 12ヶ月無料
- 新規アカウント作成後12ヶ月限定

例：
- Amazon EC2 t系小型インスタンス
- Amazon S3 一定容量
- Amazon RDS 小規模DB

### ③ Trial（トライアル）
- 期間限定で特定サービス無料

例：
- AI系
- 分析系
- 新サービス体験版

## 2. 従量課金（Pay as you go）

AWSの基本思想：
- 使った時間
- 使った容量
- 通信量
- リクエスト数
に応じて課金

例：
- EC2 → 起動時間
- S3 → 保存GB数
- Lambda → 実行回数＋時間

## 3. 料金モデルの最適化
### オンデマンドインスタンス
- 通常料金
- いつでも開始停止可能

#### 特徴
- 契約縛りなし
- 柔軟
- 単価高い

#### 向いてる用途
- 開発環境
- 検証
- 短期利用

### スポットインスタンス
- 余剰リソースを大幅割引利用

#### 特徴
- 最大90%安いこともある
- AWS都合で停止される可能性あり

#### 向いてる用途
- バッチ処理
- CI/CD
- 並列処理
- 一時的ワーカー

### リザーブドインスタンス（RI）
- 1年 or 3年利用前提で割引

#### 特徴
- 長期利用で安い
- EC2継続利用向け

**Standard RI**
- 最も割引率高い
- 柔軟性低め

**Convertible RI（コンバートRI）**
- 割引率少し下がるが変更しやすい
- インスタンスタイプ変更可
- OS変更など一部柔軟

## Savings Plans と RI の違い
- Savings Plans
今はこちらが主流

- 時間単位の利用金額コミットで割引

たとえば：
- 1時間あたり $10 利用する
- 1年契約
すると割引

### RIとの違い
| 項目       | Savings Plans | RI     |
| -------- | ------------- | ------ |
| 柔軟性      | 高い            | 低い     |
| インスタンス変更 | しやすい          | 制限あり   |
| Lambda適用 | あり（一部）        | なし     |
| 推奨度      | 高い            | 既存用途向け |


## ボリュームディスカウント
**使う量が多いほど単価が下がる仕組み**

例：
- S3保存容量増加で単価低下
- CloudFront転送量増加で割引
- データ処理量ベース割引



## 専有インスタンス系
- Dedicated Instances
- あなた専用ハードウェア上の仮想インスタンス
- 他社と物理共有しない

用途：
- コンプライアンス
- ライセンス制約

## Dedicated Hosts
- 物理ホスト1台専有
- より細かい制御可能

用途：
- Windowsライセンス持ち込み
- ソケット/コア課金ソフト

## Bare Metal Instances
- 仮想化なしで物理サーバー直接利用

用途：
- 特殊性能要件
- ハイパーバイザー制御
- 高性能DB

## コスト管理ツール
### AWS Budgets
- 予算管理ツール

例：
- 月1万円超えそう
→ メール通知

### Cost Explorer
- 利用料金分析ツール
- 見える化

### AWS Pricing Calculator
- 事前見積ツール
- 構成入力すると概算費用が出る

例：
- EC2 2台
- RDS 1台
- S3 500GB
→ 月額試算

## 最適化ツール
### AWS Compute Optimizer
- EC2サイズ見直し提案

## AWS Compute Optimizer
- **機械学習**を使って、**リソースの最適なサイズ**を提案してくれるサービス

**できること**
- EC2 / EBS / Lambda などの使用状況を分析
- 「インスタンスが大きすぎる or 小さすぎる」を判断
- 最適なインスタンスタイプを提案

**メリット**
- 無駄なスペックを削減 → コスト削減
- パフォーマンス低下のリスクも減らせる

**使うべき場面**
- EC2のコストが高い
- 適切なインスタンスサイズが分からない

## AWSコスト配分タグ
- **リソースにタグを付けて、コストを「用途別」に分解**する仕組み

例：
- Project=ECサイト
- Env=Production
- Team=Marketing

**できること**
- プロジェクト別コスト可視化
- 部門別請求
- 不要リソースの発見

**ポイント**
- タグ設計が超重要（後から整理すると地獄）
- 「必須タグルール」を作ると効果大

## AWS Application Cost Profiler
- **アプリケーション単位でコストを分析する**サービス

**できること**
- 「ユーザー単位」「機能単位」のコスト分析
- SaaSやゲームなどで特に有効

例：
- ユーザーAの利用コスト
- 機能Xがどれだけコストを消費しているか

**向いているケース**
- SaaSビジネス
- 従量課金モデルのサービス

## AWS Organization
- **複数アカウントをまとめて管理**するサービス

**できること**
- アカウントの一元管理
- 請求の統合（コンソリデーティッドビリング）
- ポリシー制御（SCP）

**メリット**
- 大規模運用で必須
- セキュリティ・コスト管理がしやすい

**典型構成**
- 管理アカウント
- 本番 / 開発 / 検証アカウント分離

## AWS Budgets
- **予算を設定して、超えそうになったら通知**するサービス

**できること**
- 月額予算設定
- 使用量ベースのアラート
- メール / SNS通知

例：
- 「今月10万円超えそう → アラート」
- 「EC2利用が急増 → 通知」

**メリット**
- コストの暴走防止
- 初心者でも必須レベル

## AWS Instance Scheduler
- **EC2やRDSをスケジュールで自動起動・停止**する仕組み

**できること**
- 夜間停止
- 土日停止
- 営業時間だけ起動

**メリット**
- 最大で70%程度のコスト削減も可能
- 手動停止のミスを防げる

**無料について**
- ソリューション自体は無料
- ただし裏で動くLambdaなどの料金は発生（微小）
