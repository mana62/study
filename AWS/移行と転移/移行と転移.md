# AWS 移行サービス
AWS の移行サービスは４系統：
- ①評価・計画
- ②サーバー移行
- ③DB/データ移行
- ④物理デバイス移行

# 1. 評価・計画フェーズ（Assess / Plan）
## AWS Application Discovery Service
- **オンプレ環境の サーバー情報・依存関係・リソース使用量を自動収集**
- **移行計画の基礎データ**になる
- 収集内容：OS、CPU/メモリ、ネットワーク通信、依存関係
- Migration Hub に統合される

## AWS Migration Hub
- **複数の移行ツール（MGN、DMS、Snow など）の 進捗を一元管理**
- 大規模移行で必須の 司令塔

# 2. サーバー/インフラ移行（Lift & Shift）
## AWS Application Migration Service（MGN）
- **AWS 推奨のサーバー移行サービス**
- **物理・仮想・他クラウド → AWS EC2** へブロックレベルで継続レプリケーション
- 最小ダウンタイム（カットオーバー数分）
- OS/アプリ/設定ごと移行

## AWS Server Migration Service（SMS）
- **VMware/Hyper‑V など 仮想マシン専用のエージェントレス移行**
- MGN が基本的に後継

# 3. DB移行・データ転送
## AWS Database Migration Service（DMS）
- **DB のオンライン移行（CDC対応）**
- **同種移行**：Oracle → RDS Oracle
- **異種移行**：Oracle → Aurora PostgreSQL
- 移行中も DB は稼働し続ける

## AWS Schema Conversion Tool（SCT）
- **異種DB移行時の スキーマ変換 を自動化**
（例：Oracle → PostgreSQL）

## AWS DataSync
- **オンプレ・他クラウド ↔ AWS の 高速ファイル転送**
- NFS/SMB/HDFS/オブジェクトストレージ対応
- 差分転送・帯域制御・整合性チェック
- 定期同期も可能

## AWS Transfer Family
- **SFTP/FTPS/FTP を マネージドで提供**
- 既存のファイル転送ワークフローを AWS に移行する用途

# 4. 物理デバイスによる大容量データ移行（Snow ファミリー）
## AWS Snowball Edge
- **10〜100TB クラスのデータ移行**
- オフライン転送（ネットワーク不要）
- Edge コンピューティングも可能

## AWS Snowmobile
- **100PB〜エクサバイト級の超大容量移行**
- トレーラーで物理搬送

# Snowball Edge 比較
| 項目 | Snowball Edge Storage Optimized | Snowball Edge Compute Optimized |
|------|--------------------------------|---------------------------------|
| 主目的 | 大容量データ移行 | データ移行 + エッジ計算 |
| ストレージ | 約80TB | 約42TB |
| 特徴 | 低コストで大量データ転送 | GPU/CPU強化、IoT/ML処理も可能 |

# まとめ
- サーバー丸ごと移行したい → MGN
- DB を止めずに移行したい → DMS + SCT
- ファイルサーバーやNASを移行したい → DataSync
- SFTPワークフローをAWSへ移行 → Transfer Family
- 10TB以上の大量データを一気に移したい → Snowball Edge
- 100TB〜PB級の巨大データ → Snowmobile
- 移行全体を管理したい → Migration Hub
- 移行前の調査・依存関係分析 → Application Discovery Service
