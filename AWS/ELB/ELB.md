# ELB
- アクセスを **複数のサーバーへ自動で振り分ける仕組み**

たとえばWebサイトに1万人が同時アクセスすると、1台のサーバーでは耐えられないため、ELBが

- ユーザーA → EC2①
- ユーザーB → EC2②
- ユーザーC → EC2③
👉 自動で負荷を分散

## ELBを使う目的
### ① スケーラビリティ（アクセス増加に強い）
- アクセスが増えたらEC2を増やして対応

例：
- 普段2台
- セール時10台
ELBが自動で振り分け

### ② 高可用性（止まりにくい）

- 1台壊れても他のサーバーへ流せる

EC2① 故障
EC2② 稼働
EC2③ 稼働

利用者は気づきにくい

## ELBの特徴
1. インスタンス間の負荷分散
- アクセスを均等に分ける

2. ヘルスチェック
- サーバーが元気か自動確認

例：
HTTP 200返る？
応答ある？

壊れたEC2には流さない

3. サブネットの柔軟性
- 複数AZ（東京a、東京cなど）にまたがって配置可能
- 災害や障害に強い

4. Auto Scaling連携
- EC2が増減しても自動でELB登録できる
- これ現場でかなり重要

5. 課金モデル
- 基本は使った分だけ課金
- 稼働時間
- 通信量
- 接続数など

6. セキュリティ制御
- HTTPS化や証明書設定可能
- ELBでSSL終端できる

7. ログ機能
- 誰がいつアクセスしたかログ保存可能
（S3などへ）

## ELBの主要機能
1. ヘルスチェック
- 死んだサーバーを自動除外

2. クロスゾーン負荷分散
- AZごとのEC2数が違っても均等に振り分け
- 例：
AZ-a 1台
AZ-c 3台
- 偏りを防ぐ

3. 暗号化通信（HTTPS）
- ユーザー ↔ ELB 間をHTTPS化
- 安全

4. スティッキーセッション
- 同じユーザーを同じEC2へ送り続ける機能
- ログイン情報をサーバー内保持してる古い構成で使うことあり

5. Deregistration Delay
- サーバー停止前に今の通信が終わるまで待つ
- 突然切断しないための機能

6. リスナー設定
- ポート番号の受付設定
- 例：
80 → HTTP
443 → HTTPS

## ELBのタイプ
### ① CLB（Classic Load Balancer）
- 昔からある旧型
- 古いシステム向け
- 新規利用は少なめ


### ② ALB（Application Load Balancer）
- 今いちばんよく使う
- HTTP/HTTPS向け

**特徴：**
- URLごと振り分け可能
- ドメインごと振り分け可能

例：
example.com/api → APIサーバー
example.com/shop → EC2別グループ

- Webサービス向け最強

### ③ NLB（Network Load Balancer）
- 超高速・低遅延・TCP/UDP向け

**使い道：**
- ゲーム
- 金融
- 高速通信
- 固定IP必要
