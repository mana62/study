## デフォルトVPC
- **AWSアカウント作成時**に最初から用意されている、**すぐ使えるネットワーク環境**

普通はVPCを自分で作って、
- CIDR決める
- サブネット作る
- ルート設定する
必要がある

でもデフォルトVPCは、最初から全部ある程度作ってあるので、すぐ Amazon EC2 を起動できる

### VPCを作る方法は２つある
## カスタムVPC
1. VPC作成
2. サブネット作成
3. インターネット経路を設定
4. VPCへのトラフィック許可の設定（ネットワークACL：サブネット単位で通信を許可・拒否するファイアウォール）

## VPCウィザード
- **VPC構成を自動で簡単作成してくれるAWSの設定補助機能**

本来VPCを手動で作るには、
- VPC作成
- サブネット作成
- ルートテーブル
- Internet Gateway
- NAT Gateway
- セキュリティ設計
など色々必要

VPCウィザードなら、**テンプレート選んで数クリックで作れる**

### よく作成されるパターン
| 構成               | 内容         |
| ---------------- | ---------- |
| Public only      | 公開サーバー向け   |
| Public + Private | Web + DB構成 |
| Private only     | 内部システム     |
| VPN付き            | オンプレ接続     |

## VPC における DNS
- VPC内で名前からIPアドレスを調べる仕組み

| 設定             | 意味          |
| -------------- | ----------- |
| DNS resolution | 名前→IP変換を有効化 |
| DNS hostnames  | EC2へDNS名付与  |

- Route 53 = DNSサービス全体
- VPC DNS = VPC内部で使う名前解決機能

| 項目  | Route 53     | VPC DNS               |
| --- | ------------ | --------------------- |
| 役割  | DNSサービス      | VPC内名前解決              |
| 対象  | インターネット / 社内 | VPC内部                 |
| 例   | example.com  | ip-10-0-1-15.internal |
| 主用途 | 公開サイト、独自ドメイン | EC2間通信                |


- VPC内部DNSは、基本的にそのVPC内、または接続されたプライベートネットワーク向けの名前解決
- 外部向けDNS = Route 53 を使うことが多い
