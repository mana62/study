# AWSのインフラ構成
```bash
世界
 └─ リージョン（地域）
      └─ アベイラビリティゾーン(AZ)
            └─ VPC（自分専用ネットワーク）
                  ├─ パブリックサブネット
                  │    └─ Webサーバー(EC2)
                  └─ プライベートサブネット
                       ├─ APサーバー
                       └─ DB(RDS)

＋追加拠点
 ├─ Edge Location（CDN拠点）
 ├─ Local Zone（都市近接拠点）
 ├─ Wavelength Zone（5G通信会社近接）
 └─ Direct Connect（専用線接続）
```

### ① リージョン（地域）
- AWSの拠点エリア

例：
Tokyo リージョン
Osaka
Virginia

**→ サービスをどこの国で動かすか決める場所**

### ② AZ（アベイラビリティゾーン）
- リージョン内の別々のデータセンター群
- 各リージョンには３つ以上のAZがある

例：
Tokyo-a
Tokyo-b
Tokyo-c

**→ 障害対策で複数AZに分散配置する**

### ③ VPC（仮想ネットワーク）
- Amazon VPC
- 専用のネットワーク空間
- VPCの仮想空間を作らない何もできない

例：
10.0.0.0/16

**→ AWS内に自社LANを作るイメージ**

### ④ サブネット
- VPCの中をさらに分割
- VPCを作成したら必ず１つ以上のサブネットを作る必要がある

⚫︎Public Subnet
インターネット接続あり
⚫︎Private Subnet
外部公開しない内部用（NATゲートウェイをパブリックサブネットに作る必要がある）

### ⑤ EC2（サーバー）
- Amazon EC2
- 仮想サーバー

例：
Webサーバー
APサーバー
バッチサーバー

### ⑥ ストレージ
- Amazon EBS = EC2用ディスク
- Amazon S3 = ファイル置き場

### ⑦ DB
- Amazon RDS
- MySQL/PostgreSQLなどを管理付きで使えるDB

### ⑧ セキュリティ
- AWS IAM = 権限管理
- Security Group = サーバー用ファイアウォール

---

- **①エッジロケーション** = コンテンツ配信に利用されるローケーション、ユーザー近くで配信、Webサイト高速化したい
- **②ローカルゾーン** = リージョンから遠い都市で、AWSサービスをより低遅延で使うための都市拠点

つまり、
- その都市にリージョンがない
- リージョンまで遠い
- 数ms〜数十msでも遅延を減らしたい
こういう時に使う

- **③Wavelength Zone** = 5Gネットワークを利用した高速アプリケーションを開発できる
- **④Direct Connect** = 社内とAWSを安全接続

| 用語         | 誰のため？   | 何したい時？         | 一言      |
| ---------- | ------- | -------------- | ------- |
| Edge       | Web利用者  | サイト表示を速くしたい    | 配信拠点    |
| Local Zone | アプリ会社   | 都市で低遅延処理したい    | 都市ミニAWS |
| DX         | 企業IT部門  | 社内とAWSを安全接続したい | 専用線     |
| Wavelength | 5Gアプリ会社 | スマホ通信を超低遅延化したい | 5G近接AWS |
