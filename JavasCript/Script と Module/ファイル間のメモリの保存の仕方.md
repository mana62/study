# メモリ内の保存
結論：
```js
import { red } from "./a.js";
```
この`red`は、値のコピーではない → **元の変数そのものを参照している**

## イメージ
普通の代入
```js
const a = 10;
const b = a;
```
これは `b = 10（コピー）`

importの場合
```js
// a.js
export let red = "RED";
```
```js
// main.js
import { red } from "./a.js";
```
これは `red → a.jsのredを直接見ている`

そのため...

```js
// a.js
export let red = "RED";

export function change() {
  red = "RED2";
}
```
export のほうで値が変わった場合、importの方も正しく変わる **（red自体を見ているため）**

```js
// main.js
import { red, change } from "./a.js";

console.log(red); // RED

change();

console.log(red); // RED2 ←変わる
```

## なぜこうなるのか
＝ **importは「メモリの住所」を共有している**
つまり： **同じデータを見ているため**

## よくある誤解
- ❌ 間違い： `import = 値をコピーしてくる`
- ⭕ 正しい： `import = 元の変数への参照（リンク）`

そのため...
- **元の値が変わると → import側も変わる**
- **同じモジュールは → 全員で共有される**

## オブジェクトだとさらに分かりやすい
```js
// a.js
export const obj = { name: "A" };
// main.js
import { obj } from "./a.js";

obj.name = "B";
// a.js 側でも
obj.name === "B"
```
👉 同じものを見てるから

## デフォルトエクスポートも同じ
```js
export default { name: "A" };
import data from "./a.js";
```
＝ これも **同じデータを参照している**

## まとめ
```bash
importはコピーじゃない
↓
元のデータを直接見ている（参照）
↓
だから値が変わると一緒に変わる
```

**import = ショートカット（リンク）**
