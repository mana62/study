# モジュールとスクリプトの違い

まず結論：
| 違い            | Script  | Module    |
| ------------- | ------- | --------- |
| import/export | ❌       | ✅         |
| strict mode   | 手動      | 自動        |
| this          | window  | undefined |
| 変数の範囲         | グローバル   | ファイル内     |
| await         | async必要 | 直接OK      |


## JavaScriptの2種類
JavaScriptには 2つの実行タイプがある
| 種類     | 説明                    |
| ------ | --------------------- |
| Script | 今まで普通に書いていたJS         |
| Module | import / exportが使えるJS |

例：
```js
<script src="main.js"></script>      <!-- Script -->
<script type="module" src="main.js"></script>  <!-- Module -->
```

## モジュールとスクリプトの違い
### ① モジュールは自動でStrict Mode
普通のScript
```js
x = 10; // エラーにならない
```
Module

```js
x = 10; // エラー
```
理由：👉 Moduleは 自動で strict mode

### ② this の値が違う
Script
```js
console.log(this);
```
結果：👉 window（ブラウザのグローバル）

Module
```js
console.log(this);
```
結果：👉 undefined

### ③ モジュールはファイルごとにスコープ
Scriptの場合
a.js
```js
const apple = "🍎";
```
b.js
```js
console.log(apple);
```
👉 見えてしまう

Moduleの場合
a.js
```js
const apple = "🍎";
```
b.js
```js
console.log(apple);
```
👉 エラー

理由：モジュールはファイル内だけで完結

他から使うには
- export
- import
が必要

### ④ 同じ関数名はエラー
Script
```js
function test(){}
function test(){}
```
👉 OK

Module
```js
function test(){}
function test(){}
```
👉 エラー

＝ Moduleの方が 安全

### ⑤ Moduleでは await が直接使える
普通のScript
```js
await fetch(url)
```
👉 エラー

必ず async が必要
```js
async function test(){
  await fetch(url)
}
```

Module
```js
await fetch(url)
```
👉 そのまま使える

これを **Top Level Await** と言う

## まとめ
| 違い            | Script（従来のJS） | Module（ES Modules） |
|-----------------|--------------------|-----------------------|
| import/export   | ❌ 使えない         | ✅ 使える（export / import） |
| strict mode     | 手動で "use strict" | 自動で strict mode     |
| this            | window（グローバル） | undefined（モジュールスコープ） |
| 変数の範囲       | グローバルに漏れやすい | ファイル内に閉じる（スコープが分離） |
| await           | async 必要          | トップレベル await が使える |

⚫︎一番大事な理解
Moduleは **「ファイルごとに独立した安全なJS」**
だから
- 変数が外に漏れない
- import/exportで管理
- strict mode
