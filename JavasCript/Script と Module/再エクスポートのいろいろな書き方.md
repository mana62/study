# 再エクスポートのいろいろな書き方
＝ 再エクスポート =「importしてexportする処理を、1行で省略して書ける仕組み」
＝ **インポートしたものは、そのままエクスポートできる（＝再エクスポート）**

## 再エクスポートとは？
```js
// a.js
export const a = "hello";

// b.js
import { a } from "./a.js";
export { a };
```
👉 これをまとめて書ける ↓（上記と同じ意味）

```js
export { a } from "./a.js"; // importしてexportする処理を、1行で省略して書ける
```

👉 これが「再エクスポート」
👉 データをコピーしてるわけじゃない
👉 同じ値を参照（共有）しているだけ

```bash
a.js → b.js → main.js
   ↑ 同じデータを参照
```

## 普通のexportとの違い
● 普通のexport
```js
export const a = 1;
```
👉 自分で作ったものを外に出す

● 再エクスポート
```js
export { a } from "./a.js";
```
👉 他のファイルのものを、そのまま外に出す

## 循環参照の注意
👉 こういう状況
```bash
A → B → A（戻ってくる）
```
このとき：
- import自体は先に準備される（使える）
- でも中身がまだ未初期化だとエラー

**ポイント**
- 関数宣言 → OK（巻き上げされる）
- const / let → NG（初期化前に使えない）

## よく使う書き方まとめ
### ① まとめて再エクスポート
```js
export { a, b } from "./module.js";
```

### ② 名前を変える
```js
export { a as newName } from "./module.js";
```

### ③ デフォルトを再エクスポート
```js
export { default } from "./module.js";
```

または
```js
export { default as myFunc } from "./module.js";
```

### ④ 全部まとめて
```js
export * from "./module.js";
```
👉 ただし： default は含まれない

### ⑤ defaultも含めたい
```js
export * from "./module.js";
export { default } from "./module.js";
```

### ⚠️ 注意
- 名前が被ると、👉 明示的な export が優先される
```js
export const a = 1;
export * from "./module.js"; // moduleのaは無視される
```
- `*` 同士で被るとエラー
```js
export * from "./a.js";
export * from "./b.js"; // 両方に a があるとエラー
```

## まとめ
- **インポートしたものは、そのままエクスポートできる（＝再エクスポート）**
- 再エクスポートには主に4つの書き方がある

```js
export { a as b } from "./a.js";
export { default } from "./a.js";
export * from "./a.js";
```

⚠️ 注意
- defaultは * に含まれない
- 名前かぶるとエラー or 優先順位あり（明治的に書かれているもの優先）

- 再エクスポート = **import + export を一発で書く**
- データはコピーじゃなくて参照共有

循環参照では：
  - 関数 → OK
  - const/let → エラーになりやすい
- export * は便利だけど：
  - defaultは含まれない
  - - 名前衝突に注意
