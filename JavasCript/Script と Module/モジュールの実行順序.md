# モジュール（import / export）の実行順序

## 基本ルール
＝ **importされたファイルが先に実行される**

例：
```js
// main.js
import "./a.js";
console.log("main");
```
```js
// a.js
console.log("a");
```
結果：
```js
a // importが先だからaが先に実行
main
```
＝ **import先 → import元**の順で実行される

## importはどこに書いても順序は同じ
```js
console.log("start");

import "./a.js";

console.log("end");
```
実行順
```js
a.js
start
end
```
理由：**JavaScriptは解析時にimportを先に処理するため**
ただし実務では **ファイルの一番上に書く** のが一般的

## import文同士は上から順番
```js
// main.js
import "./a.js";
import "./c.js";
```
実行順
```js
a.js
c.js
main.js
```
つまり： **import文の順番は実行順に影響する**

## importだけして値を受け取らない書き方
```js
import "./a.js";
```
これは `a.js`を実行するだけ という意味
＝ **実行されるのは トップレベルのコード**

#### トップレベルとは
- **関数やクラスの外に書かれているコード**
- ファイルの一番外側のコード

例：
```js
console.log("実行される"); // トップレベル

function test() {
  console.log("実行されない");
}
```

**よく使う例**
- polyfill
- 設定ファイル
- 初期化処理

#### グローバールとの違い
|           | グローバル   | トップレベル   |
| --------- | ------- | -------- |
| スコープ      | プログラム全体 | そのファイルだけ |
| windowに入る | 入る      | 入らない     |
| モジュール     | 使わない    | 使う       |

## importされたファイルは1回しか実行されない
例えば：
```js
main → a
main → b
a → c
b → c
```
この場合
```js
c.js
a.js
b.js
main.js
// dはcと被ってるから一回しか実行されない
```
ただし **c.js は1回だけ実行** 同じモジュールは **キャッシュされる**

## 循環参照（Circular Import）
例：
```bash
a → b
b → a
```
この場合 **無限ループはしない**
- JavaScriptが **循環部分を無視する**
- これを **循環参照（Circular Dependency）** と言う

## 実行順の考え方
＝ **帰りがけ順** 「依存関係の一番下から実行」

例：
```js
main
 ↓
a
 ↓
b
```
実行順：
```js
b
a
main
```

## 重要ルール
- あるファイルが実行される条件
  - **importしているファイルがすべて実行完了していること**

例：
```js
main → a → b
```

順序
```js
b
a
main
```

## トップレベル await がある場合
例：
```js
// a.js
await fetch(...)
console.log("a")
```
この場合
- a.js が 完了するまで
- main.js は 実行されない

つまり：**import先が終了するまで待つ**

## まとめ
### ① import先が先に実行
```bash
a.js → main.js
```

### ② import文の順番も重要
```bash
import A
import B

↓

A → B → main
```
### ③ 同じファイルは1回だけ実行
```bash
a → c
b → c

↓

c は1回だけ
```

### ④ 実行は依存関係の一番下から
```bash
b → a → main
```

### ⑤ importだけ書くと「実行だけ」
```bash
import "./a.js";
```
