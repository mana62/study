# バンドラー
**いろんなファイルをまとめること**

## バンドラーを使う理由
- HTTP通信を減らすため
 → 1つの大きなファイルにまとめることでリクエスト数を減らす

- コード最適化のため
 → 圧縮（minify）、不要コード削除（tree-shaking）、高速化

- ライブラリを簡単に使うため
 → npm の依存関係をまとめてブラウザで使える形に変換

- いろんな種類のファイルを扱うため
 → TS、CSS、画像、JSON などを JS に変換してまとめる

- HMR（Hot Module Replacement）
 → 保存した瞬間にブラウザが自動更新される

- ESM を古いブラウザでも動く形に変換するため
 → 互換性のための変換（transpile）

👉 現代のフロントエンド開発ではほぼ必須

## バンドラー種類
| バンドラー     | 特徴                                               |
| --------- | ------------------------------------------------ |
| webpack   | 最も歴史が長い。設定が重いが強力。                                |
| rollup.js | ライブラリ向け。軽量で tree-shaking が強い。                    |
| esbuild   | Go製で超高速。Vite の内部でも使われる。                          |
| rolldown  | Rust製。Rollup互換を目指す次世代バンドラー。                      |
| vite      | バンドラーというより「開発サーバー＋ビルド」。内部で esbuild と Rollup を使う。 |
| Rsbuild   | Rust製。Webpack互換を目指す次世代ツール。                       |
