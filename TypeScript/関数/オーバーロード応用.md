# オーバーロード応用
- **オーバーロードの型がついた変数には、そのオーバーロードの全パターンに対応した関数しか入れられない**

## オーバーロードとは？
- **同じ関数名で、入れる値によって返ってくる値が変わる仕組み**

```ts
// 文字列を入れたら文字列が返る
upperHello("hello")  // → "HELLO"

// 数字を入れたら数字が返る
upperHello(3)        // → 3000
```
→ **これを型で表現するのがオーバーロード**

## ① 関数は変数に代入できる
```ts
function upperHello(x: string): string { ... }

// 関数を変数に代入できる
const fn = upperHello // 関数代入
```

## ② オーバーロードを「型」として書くとこうなる
**インターフェースを使ってオーバーロードの型を表現できる**

```ts
// これがオーバーロードの「型」
interface UpperHelloType {
  (x: string): string   // 文字列を入れたら文字列が返る
  (x: number): number   // 数字を入れたら数字が返る
}
```
**この型の変数には、文字列にも数字にも対応した関数しか入れない**

## ③ 重要ポイント‼️
```ts
// ✅ OK → 文字列にも数字にも対応している
const fn: UpperHelloType = (x: string | number) => { ... }

// ❌ NG → 文字列にしか対応していない
const fn: UpperHelloType = (x: string) => { ... }
```
なぜNGかというと…

```bash
オーバーロードの型は
「文字列を入れても動く」
「数字を入れても動く」
と約束している

なのに文字列しか対応していない関数を入れたら
数字が来た時に動かない！ → 約束違反 → エラー
```

## ④ 全体をまとめると
```bash
オーバーロードの型を持つ変数には

❌ 一部にしか対応していない関数
✅ すべてのパターンに対応した関数（ユニオン型を使う）

しか入れられない
```
コードだと

```ts
interface UpperHelloType {
  (x: string): string
  (x: number): number
}

// ✅ string | number（ユニオン型）で全パターンに対応
const fn: UpperHelloType = (x: string | number) => {
  if (typeof x === "string") return x.toUpperCase()
  return x * 1000
}
```

```ts
オーバーロードで型を指定した変数には
「指定した全パターンに対応できる関数」しか入れられない

// オーバーロードの型
// stringを入れたらstringが返る
// numberを入れたらnumberが返る
// と約束している

// → 代入する関数は string にも number にも対応している必要がある
// → ユニオン型（string | number）を使って全パターンを受け取れるようにする
```
👉 「全ての型を使う必要がある」というより「全ての型に対応できる必要がある」というイメージ
