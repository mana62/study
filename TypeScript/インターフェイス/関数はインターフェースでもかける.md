# 関数をインターフェイスで書く方法
- **関数＝オブジェクト**
- 関数もオブジェクトの一種
- だから **interface で定義できる**

## 普通の関数
```ts
type Add = (a: number, b: number) => number;
```
意味：「数字2つ受け取って、数字を返す関数」

## 同じことをinterfaceでも書ける
```ts
interface Add {
  (a: number, b: number): number;
}
```
意味は完全に同じ：「数字2つ → 数字を返す関数」

### ポイント
- 普通のinterface → オブジェクトの形
- これは → **関数の形（関数型）**

## コールシグネチャとは
- **インターフェイスの中で 関数の型 を定義する書き方**のこと
- つまり
  - 引数は何か
  - 戻り値は何か
  - どんな関数なのか
を オブジェクトのプロパティとしてではなく、**関数そのものとして定義する書き方**

```ts
interface Add {
  (a: number, b: number): number;
}
```

## new がつくと意味が変わる
```ts
interface PersonConstructor {
  new (name: string): Person;
}
```
意味：「これは new で呼ぶ関数（コンストラクタ）」

### ポイント
- ( ) → 普通の関数
- new ( ) → コンストラクタ関数

## 基本はtypeで関数を定義する方が多い
- 関数の型を作るだけなら type のほうがシンプルで一般的

### interface のコールシグネチャが存在するの？
#### ① オーバーロードを自然に書ける
```ts
interface ToString {
  (value: number): string;
  (value: boolean): string;
}
```
- type でもできるけど、interface のほうが読みやすい

#### ② 関数にプロパティを持たせたいとき
- 関数自体がプロパティを持つケース（ライブラリでよくある）

```ts
interface Counter {
  (): number;
  count: number;
}

const c: Counter = () => 1;
c.count = 10;
```
- type でも書けるけど、interface のほうが自然

#### ③ ライブラリの型定義（d.ts）でよく使われる
- Express、React、Node.js の型定義は interface のコールシグネチャが多い

理由：
- 拡張（extends）がしやすい
- 宣言マージができる（type にはできない）

| 目的                         | おすすめ |
|------------------------------|----------|
| 普通の関数の型を作りたい     | type     |
| オーバーロードしたい         | interface|
| 関数にプロパティを持たせたい | interface|
| ライブラリの型定義を書く     | interface|
| React/実務の一般的な関数型   | type     |
