# abstract class（アブストラクト）
- **継承されるためだけに存在する**、未完成のクラス

# TypeScript 抽象クラスの特徴
| 特徴 | 説明 |
|------|------|
| インスタンス化できない | new できない（未完成だから） |
| 継承専用 | 子クラスに継承される前提で作る |
| 抽象メソッドを持てる | 中身のないメソッドを定義できる |
| 子クラスに実装を強制できる | 抽象メソッドは必ず override しないとエラー |
| static は使える | クラスに属するのでアクセス可能 |
| JS には存在しない | TS の型チェックだけの機能（JS では消える） |
|クラス自体にもabstractを付ける | クラス自体をabstractクラスにする必要がある |

## 抽象メソッドとは？
- **中身が書かれていないメソッド** → **子クラスが必ず実装**しないといけない
- 定義するだけで、実装はこクラスに任せる

```ts
// abstractを付ける必要がある
abstract class Job {
  abstract execute(): void; // ← 中身なし。子クラスが必ず実装
}
```

## 抽象クラスの正しい書き方
```ts
abstract class Job {
  abstract exampleJob(): string; // ← 型が必要
}
```
**「ポイント」**
- **abstract は クラスの前 と メソッドの前 の両方に付ける**
- **抽象メソッドには 型が必須**
- **中身 {} は書けない**（必ず書いあたらダメ）

## 子クラスは必ず実装しないといけない
```ts
class Programmer extends Job {
  exampleJob(): string {
    return "プログラマーの仕事です";
  }
}
```
もし実装しないと、エラー

```ts
class Programmer extends Job {}
// ❌ エラー：exampleJob を実装していません
```

## 抽象クラスは new できない
```ts
new Job(); 
// ❌ エラー：抽象クラスはインスタンス化できません
```
理由：**未完成（抽象メソッドがある）だから**

## static （newしなくても使えるようにすること） は使える
- 抽象クラスでも static は使える
- static は **クラスに属する ので、インスタンス化できなくても関係ない**

```ts
abstract class Job {
  static version = "1.0";
}

console.log(Job.version); // OK
```

## JS に変換すると abstract は消える
- **TypeScript の abstract は 型チェックのためだけの機能**

コンパイル後の JS では：
- abstract は完全に消える
- 抽象メソッドは存在しない（ただの空のクラスになる）

つまり：
- 抽象クラスは **TS のコンパイル時だけ意味がある** 機能

## 抽象クラスは何のために存在するの？
- **「設計の強制」 と 「共通処理の提供」** の2つ

### 目的1：子クラスに必ず実装させるため
- 抽象メソッドは「このメソッドは絶対に必要だよ」という ルール を作る

```ts
abstract class Job {
  abstract work(): void;
}

// 子クラス
class Programmer extends Job {
  work() {
    console.log("コードを書く");
  }
}
```
- → 実装漏れを防げる
- → 大規模開発でめちゃくちゃ重要

### 目的2：共通処理は親に書き、個別処理は子に任せる
- 抽象クラスは**「未完成の部分（抽象メソッド）」と「完成している部分（通常メソッド）」を両方持てる**

```ts
abstract class Job {
  abstract work(): void;

  log() {
    console.log("作業開始");
  }
}

class Designer extends Job {
  work() {
    console.log("デザインする");
  }
}
```
- log() は共通処理
- work() は子クラスごとに違う処理
→ 共通化と個別化を両立できる

## まとめ
- 抽象クラスは「事故を防ぐための安全装置」
- 大規模開発でのバグ・実装漏れ・設計崩壊を防ぐために存在する
- 共通の型ルールを強制しつつ、子クラスに実装を任せるための未完成の設計図


- 抽象クラスは **テンプレート** なんだよ
    - 必須項目（抽象メソッド）
    - 共通項目（通常メソッド）
    - ルール（型）
これをまとめて作れる
