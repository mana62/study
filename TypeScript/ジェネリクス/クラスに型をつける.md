# クラスに型をつける
- ジェネリクスとは **「型を後から決められる仕組み」**
- クラス名の **右に <T> と書く**と、**インスタンスを作るときに型を決められる**
- クラス・関数・インターフェイスを **「型だけ差し替えて再利用したい」と**きに使う仕組み

## クラス例
```ts
class Database<T> {
  private data: T[] = [];

  add(item: T): void {
    this.data.push(item);
  }
  get(): T[] {
    return this.data;
  }
}

// 文字列専用DBを作る
const strDB = new Database<string>();
strDB.add("apple");
strDB.add("banana");
// strDB.add(123); ← ❌ エラー！ちゃんとはじかれる

// 数値専用DBを作る
const numDB = new Database<number>();
numDB.add(10);
numDB.add(20);
```
👉 ジェネリクスなら **「同じクラス定義」から、型の違うDBを何個でも作れる**
👉 後から型を自由に決められる

## ユニオン側ではダメな理由
```ts
// ❌ ユニオン型でやると…
class Database {
  private data: (string | number)[] = [];
  add(item: string | number) { // stringもnumberも混入できてしまう
    this.data.push(item);
  }
}
const db = new Database();
db.add("apple");
db.add(123);  // ← これも通ってしまう！文字列だけ入れたいのに
```
👉 ユニオン型だと「文字列専用DB」「数値専用DB」を作れない
👉 型が混ざってしまう

## extends で「使える型を制限する」
```ts
// T は string か number か boolean だけOK
class Database<T extends string | number | boolean> {
  private data: T[] = [];
  add(item: T) { this.data.push(item); }
}

// ✅ これはOK
new Database<string>();

// ❌ これはエラー（オブジェクトは使えない）
new Database<{name: string}>();
```
👉 extends は **Tに制限・ルールを付ける**

## まとめ（クラスのジェネリクス）
- ユニオン型だと「文字列も数値も両方入れられる箱」しか作れない
- ジェネリクスなら「文字列専用」「数値専用」と型ごとに別の箱を作れる
