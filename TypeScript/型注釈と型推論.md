# 型注釈と型推論の違い

## 型推論 (Type Inference)
- TypeScript が **コードから自動的に型を推測**する仕組み
- 推論された型はその後 **固定されて安全性を保証**する
- 冗長な型を書かずに済むので **読みやすく保守しやすい**

## 型注釈 (Type Annotation)
- 開発者が **明示的に型を書く**方法
- 推論できない場合や、意図を明確にしたい場合に使う
- 間違った型を書くと「嘘の型」になる可能性がある

## 型注釈はいつ書くの？
＝ 型注釈を書くのは 必要なときだけ

🟩 ① 関数の引数・戻り値（特に公開API）
```ts
function add(a: number, b: number): number {
  return a + b;
}
```
理由：外から呼ばれる関数は型を明示した方が安全。

🟩 ② 変数に関数を入れるとき（コールバック含む）
```ts
const calc: (a: number, b: number) => number = add;
```
理由：関数の形を保証したいから

🟨 ③ 推論が弱いとき（例：null 初期化）
```ts
let user: User | null = null;
```

🟥 ④ それ以外は基本書かない
```ts
let name = "Taro"; // string と推論される
let age = 20;      // number と推論される
```
→ 型注釈を書くと逆に冗長でミスの原因になる

## まとめ
- **基本は型推論に任せる**
- **必要なところだけ型注釈を書く**
- これが TypeScript の推奨スタイル
