# タイプガード（型を絞り込む）
- 基本的に **ユニオン型（A | B）** のときに使うもの
- if 文の中で「この値は〇〇型だよ」と TypeScript に教える仕組み
  - **boolean を返す関数**
  - 返り値の型が **value is 型** になっている

## 例
- 🍎 例：袋の中に「リンゴかミカン」が入っている
- 袋の中身：Apple | Orange
- でも、取り出してみないとどっちかわからない。
- そこで：

```ts
// これだけでは Apple か Orangeどっちかわからない
type Fruit = Apple | Orange;


if (isApple(fruit)) {
  // ここでは fruit は Apple と確定
}
```
- これが **タイプガード**

## タイプガードの書き方
### 方法① typeof
- **プリミティブ型（string, number, boolean）**に使える

```ts
function printUpper(x: string | number) {
  if (typeof x === "string") {
    return x.toUpperCase(); // OK
  }
}
```

### 方法② in 演算子
- 「このプロパティがある？」で判定

```ts
type Worker = Engineer | Blogger;

function profile(worker: Worker) {
  // workerにroleがあるかtrue or falseでチェック
  if ("role" in worker) {
    worker.role; // Engineer と確定
  }
}
```
### 方法③ instanceof
- クラスに使う

```ts
if (pet instanceof Bird) {
  pet.fly(); // Bird と確定
}
```

## いつ使うのか？
- ユニオン型（A | B）を安全に扱いたいとき
- プロパティが存在するか確認したいとき
- クラスの種類を判別したいとき

- ユニオン型（A | B）を使うと、TS はこう思う：
  - 「A かもしれないし B かもしれないから、どっちのメソッドも安全に使えないよ」
  - そこでタイプガードを使うと、
  - 「この if の中では A だよ」と TS に確定させられる

## 存在する意味
- TypeScript は「実行時の値」を知らないから
- だから開発者が：「この if の中では、これは string だよ」と教えてあげる必要がある

## ポイント
- **boolean を返す関数**
- 返り値の型が **value is 型** になっている
- これが揃うと TS が「なるほど、型を絞るね」と理解する

## value is 型とは
- 「この関数が true を返したら、value はこの型だよ」と TypeScript に保証する宣言
