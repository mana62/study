# ユーティリティ型
- ユーティリティ型とは、**TypeScript が最初から用意してくれているジェネリクスを使った便利な型たち**

## ① Partial<T> ： 全部オプションにする
- Partial を付けることで、自動的に全てのプロパティにオプショナルチェーン(?)が付く

```ts
interface Todo {
  title: string;  // 必須
  text: string;   // 必須
}

type PartialTodo = Partial<Todo>;
// ↓ こうなる
// { title?: string; text?: string; }

// どっちかだけでもOKになる
const todo: PartialTodo = { title: "買い物" }; // ✅ text なくてもOK
```
❗️ 更新フォームで「一部のフィールドだけ更新したい」ときによく使う

## ② Readonly<T> ： 全部読み取り専用にする
- Readonly を付けることで、自動的に全てのプロパティが、readonly になり、書き込み不可になる

```ts
type ReadonlyTodo = Readonly<Todo>;
// ↓ こうなる
// { readonly title: string; readonly text: string; }

const todo: ReadonlyTodo = { title: "買い物", text: "牛乳を買う" };
// todo.title = "変更"; ← ❌ エラー！変更できない
```

## ③ Array<T> ： 配列のジェネリクス版
- `string[]` と `Array<string>` は同じ意味を表す

```ts
// この2つは全く同じ意味
// どっちでもOK
const fruits: string[] = ['banana', 'kiwi'];
const fruits: Array<string> = ['banana', 'kiwi'];
```

## ④ Promise<T> ： 非同期の返り値の型
- Promise<T> は「非同期処理が成功したときに返ってくる値の型は T だよ」という宣言

```ts
type User = {
  name: string;
  age: number;
};


// Promiseが解決したときの値の型を指定できる
async function fetchUser(): Promise<User> {
  const res = await fetch("/api/user");
  return res.json();
}

// fetchUser() の結果は User 型と保証される
const user = await fetchUser();
console.log(user.name); // ✅ nameがあることが保証されている
```
- async function は必ず Promise を返す
- Promise<User> と書くことで → 「この関数が返す Promise の中身は User 型だよ」と保証する
- user は User 型 と確定しているので：
  - name があることが保証される
  - age もあることが保証される
- 間違ったプロパティを書くとエラーになる

## まとめ
- Partial・Readonly・Array・Promise などは全部ジェネリクスで作られた「TypeScript が最初から用意している型」
