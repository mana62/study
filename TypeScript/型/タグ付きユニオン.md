# タグ付きユニオン
- 基本的に **ユニオン型（A | B）** のときに使うもの
- **ユニオン型に 種類を示すタグ をつけて、判別しやすくする**方法
- **タグ付きユニオンはタイプガードの一種**
  - タグ付きユニオンは 種類を示す名札つきのユニオン型
  - タグ付きユニオンは 最強のタイプガード みたいなもの（タイプガードより安全、意味はほぼ同じ）

🚗 例：車の種類を判別する
```ts
type Car =
// typeで識別するタグを作る
  | { type: 'gasoline'; fuel: number }
  | { type: 'electric'; battery: number }
```
switch で簡単に判別できる：

```ts
switch (car.type) {
  case 'electric':
    console.log(car.battery);
}
```

例：
```ts
type Dog = {
  kind: 'dog';
  bark: () => void;
}

type Bird = {
  kind: 'bird';
  fly: () => void;
}

type Pet = Dog | Bird; // typeがタグ
```

## 何が嬉しいの？
### ① 判別が超簡単
```ts
if (pet.kind === 'bird') {
  pet.fly(); // Bird と確定
}
```

### ② in演算子 より安全
- "fly" in pet は「プロパティ名の typo に気づけない」

### ③ instanceof より確実
- クラスじゃなくても使える（オブジェクトでもOK）

## タグ付きユニオンはタイプガードの一種
- しかも **自動で型が絞れる** という点で最強
  - typeof → プリミティブ限定
  - in → プロパティ名の typo に弱い
  - instanceof → クラス限定
  - タグ付きユニオン → どんな型でも安全に判別できる

## いつ使うのか？
- ユニオン型の種類を安全に判別したいとき
- API のレスポンスが複数パターンあるとき
- 状態管理（Redux など）

## 存在する意味
- **in や instanceof よりも 明確で安全**

## ポイント
- **kind や type などの タグ を必ず持たせる**
- **switch 文と相性が良い**
- 間違いが起きにくい
