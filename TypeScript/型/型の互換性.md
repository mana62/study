# 型の互換性
## 1. 基本ルール（2つ）
TypeScriptの互換性はこの2つがベース：
- **構造的型付け**：形が同じなら同じ型として扱う
- **部分型**：「取れる値の範囲が広い型」には代入できる

### 部分型とは？
まず「型」とは **「入れられる値の集合」**

```bash
string型 = 世界中のすべての文字列が入れられる
         = "hello", "bye", "あいうえお", "xyz123"...（無限）

"hello"型 = "hello"という文字列だけしか入れられない
          = "hello" のみ
```

つまり：
```bash
string型  ┌─────────────────────────┐
          │  "hello", "bye",        │
          │  "あいうえお", ...      │
          │  ┌──────────┐          │
"hello"型 │  │ "hello"  │          │
          │  └──────────┘          │
          └─────────────────────────┘
```
⚫︎「hello型」はstring型の中に収まっている → これが「部分型」
⚫︎「hello型はstring型の部分型」という

## 2. プリミティブのリテラル型
**number・booleanのリテラル型も同じルール**

| 左辺（代入される側） | 右辺（代入する値） | 代入可否 | 理由 |
|----------------------|----------------------|----------|-------|
| string               | "hello"              | ✅ OK     | string は「文字列全体」を表す広い型で、"hello" はその一部（狭い型）だから入る |
| "hello"              | string               | ❌ NG     | "hello" は特定の 1 文字列だけを許す狭い型で、string は範囲が広すぎて入らない |

### プリミティブとは？
- JavaScriptで **「これ以上分解できない基本的な値の種類」のこと**

| 型        | 例                         | 説明                         |
|-----------|----------------------------|------------------------------|
| string    | "hello", "bye"             | 文字列                       |
| number    | 1, 3.14, -5                | 数値（整数・小数どちらも）   |
| boolean   | true, false                | 真偽値                       |
| null      | null                       | 値が「存在しない」ことを示す |
| undefined | undefined                  | 変数が「未定義」である状態   |

⚠️ オブジェクト {} や配列 [] はプリミティブではない（中身をバラせるため）

## 3. Enum（⚠️ 例外）
**通常の部分型ルールが破られる特殊ケース**

```ts
enum Color { Red, Blue }  // 実態は 0, 1

let c: Color = 0   // ✅ numberをEnumに入れられる（本来NG なはず）
let n: number = Color.Red  // ✅ 逆もOK（数値Enumのみ）
```
- numberとEnumは相互に代入できる（数値Enumのみ）
- 別のEnum同士は代入不可（形が同じでもNG）
- Enumは「名前的型付け（Nominal Typing）」で扱われる
- → 型安全の穴になるので扱いに注意

### Enum型とは？
**「決まった選択肢だけ使いたい」ときに使う型**

例：
```ts
// Enumなし → 数字の意味がわからない
let signal = 0  // 0って何？赤？青？

// Enumあり → 意味がわかる
enum Signal {
  Red,    // = 0
  Yellow, // = 1
  Green,  // = 2
}

let signal: Signal = Signal.Red  // 明らかに赤信号とわかる
```
⚠️ 内部的には数字（0, 1, 2...）として扱われている
これがNumberとの互換性問題につながっている

```ts
let signal: Signal = 0  // ✅ なぜか数字も入れられてしまう（型安全の穴）
```
Enumは型でもあり、値でもある少し特殊な存在

### Nominal Typing（名前的型付け）とは？
Structural Typing（構造的型付け）＝ TypeScriptの基本
形が同じなら同じ型とみなす

```ts
interface Dog { name: string }
interface Cat { name: string }

let dog: Dog = { name: "ポチ" }
let cat: Cat = dog  // ✅ 形が同じだからOK！名前が違っても関係ない
```
Nominal Typing（名前的型付け）＝ 名前が違えば別物
「形が同じでも、名前が違えば別の型とみなす」

```ts
enum Color  { Red, Blue }
enum Coffee { Small, Large }

let color: Color = Coffee.Small  // ❌ 中身は同じ数字でも名前が違うからNG
```

つまりNominal Typingとは：
```bash
**形（構造）じゃなくて「名前」で型を区別するルール**

TypeScriptは基本Structural（形で判断）だけど
EnumとprivateつきのClassだけ例外的にNominal（名前で判断）になる
```

## 4. 関数（⚠️ 引数は逆！戻り値は順通り）
**呼ばれる引数の数：少ない→多いはOK、多い→少ないはNG**

```ts
type TwoArgs = (a: string, b: string) => void
type OneArg  = (a: string) => void

使う時の引数 少ない → 多いはOK ✅
let fn: TwoArgs = (a: string) => { console.log(a) }
// TwoArgsとして呼ばれる時は引数2つ渡される
fn("hello", "world")
// でも関数の中では1つしか使わない → 残りは無視される
// JavaScriptの仕様で余分な引数は無視されるのでOK

使う時の引数 多い → 少ないはNG ❌
let fn: OneArg = (a: string, b: string) => { console.log(a + b) }
// OneArgとして呼ばれる時は引数1つしか渡されない
fn("hello")
// でも関数の中でbを使おうとする → bがない！ → 動かない
```
**戻り値：通常の部分型ルールと同じ（範囲が狭い方を返すのはOK）**

✅ ポイント
```bash
「呼び出す側が渡す引数」より「関数が要求する引数」が多いとNG
「呼び出す側が渡す引数」より「関数が要求する引数」が少ないのはOK（余りは無視）
```

### 関数の型指定、インターフェース以外にもある？
下記３つの方法：
```ts
// ① インターフェース
interface Fn {
  (x: string): string
}

// ② type（型エイリアス）← 一番よく使う
type Fn = (x: string) => string

// ③ 直接書く
const fn: (x: string) => string = (x) => x.toUpperCase()
```
👉 実際の現場ではtypeを使うことが一番多い
インターフェースで書けるのは「関数もオブジェクトだから」という背景があるだけで、普通はtypeで書く

## 5. クラス
基本はオブジェクトと同じ（形が同じならOK）
**基本はオブジェクト・インターフェースと同じ（構造的型付け）**
⚠️ ただし private / protected が一つでもあると別ルールに！

```ts
class Person { name: string = "Peter" }
class Car    { name: string = "Prius" }

let p: Person = new Car()  // ✅ 形が同じだからOK
```
privateがあると別ルールになる ⚠️
```ts
class Person { private name: string = "Peter" }
class Car    { private name: string = "Prius" }

let p: Person = new Car()  // ❌ 形が同じでもNG！
let p: Person = new Person()  // ✅ 同じクラスのみOK
```
なぜかというと：
```bash
privateはそのクラスの内部でだけ使う秘密のデータ

「名前が同じprivateプロパティがある」からといって
全然別のクラスのデータを入れるのは危険

→ privateがある時点でNominal Typing（名前で判断）に切り替わる
→ 同じクラスから作ったインスタンスしか受け付けない
```

- privateがあると**名前的型付け（Nominal Typing）**になる
- つまり同じクラスから作ったインスタンスしか受け付けない

## 6. 型アサーション（as）のルール
asは型を「強制変換」するやつ
**as は「緩く」も「厳しく」も変換できる**：
```ts
let x = "hello" as number  // これはできる？できない？
```
ルール：
```ts
どちらか一方が、もう一方の部分型であればasが使える
（つまり、まったく関係ない型同士はasできない）
```
具体例：
```ts
// ✅ 緩くする（小さい型 → 大きい型）
let x = 30 as number          // 30はnumberの部分型 → OK

// ✅ 厳しくする（大きい型 → 小さい型）
let x = someNumber as 30      // numberを30に絞る → OK

// ❌ まったく無関係
let x = "hello" as number     // stringとnumberは無関係 → NG

// 無関係なものを無理やりasしたい場合は二段階
let x = "hello" as unknown as number  // 一回unknownを経由すればできる（非推奨）
```

両方向から互換性チェックをして、どちらかが通ればasが使える

## まとめ
| ケース | ルール | 備考 |
|--------|--------|-------|
| 基本部分型（サブタイプ） | 広い型に代入 OK | 例：string ← "hello" は OK、逆は NG |
| 構造的型付け | 形（プロパティ構造）が合えば代入 OK | TypeScript の基本思想。名前は関係ない |
| Enum | number と互換性あり | number ← Enum は OK、Enum ← number は危険（型安全の穴） |
| 関数の引数 | **少ない → 多い** は OK（逆は NG） | JS の仕様に基づく。コールバックでよく出る |
| 関数の戻り値 | 通常の部分型と同じ | 戻り値は「広い ← 狭い」が OK |
| クラス（private/protected） | 同じクラスのみ互換性あり | この場合だけ “名前的型付け” になる |
