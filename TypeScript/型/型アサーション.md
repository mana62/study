# 型アサーション （as）
- TypeScript が **型を広く取りすぎて** 邪魔なときに、開発者が「これはこの型で扱っていいよ」と指示する仕組み

例：
- TypeScript は慎重すぎるので、見えないものは全部広い型と思ってしまう
```ts
const el = document.getElementById("input");
```
- TS の判断：el は "HTMLElement かもしれないし null かもしれない"
- でも自分は 「このIDは絶対 input 要素だ」 と知っている

そこでこう書く：
```ts
const el = document.getElementById("input") as HTMLInputElement; // as を使う
```

## 書き方の例
### 方法① as 型名
```ts
const input = document.getElementById("input") as HTMLInputElement;
input.value = "hello";
```

| HTMLタグ | TypeScript の型 |
|----------|------------------|
| `<div>`  | `HTMLDivElement` |
| `<span>` | `HTMLSpanElement` |
| `<input>` | `HTMLInputElement` |
| `<form>` | `HTMLFormElement` |

### 方法② <型名>（JSX では使えない）
```ts
const input = <HTMLInputElement>document.getElementById("input");
```
- React/JSX では <div> と区別できないので 非推奨

## 変数の型を強制的に変える
```ts
let value: unknown = "hello";
const str = value as string; // string として扱う
```

## いつ使うのか？
- DOM 操作（document.getElementById）
- TypeScript が型を広く取りすぎて邪魔なとき
- API レスポンスの型が不完全
- ライブラリの型が弱いとき
- null を無視したいとき

## 存在する意味
- TypeScript は安全だけど、時々 慎重すぎる
- その慎重さを突破するための仕組み

## ポイント
- 安全性は保証されない（自己責任）
- できればタイプガードを使う方が安全
- React では as を使うのが一般的
