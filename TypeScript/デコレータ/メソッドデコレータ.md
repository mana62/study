# メソッドデコレータ
- メソッドが呼ばれる前後で、**処理を横取りできる仕組み**
- メソッドデコレータは **３つの引数を取る**
- メソッドはデフォルトではプロトタイプの中に入る
- メソッドの上に@を書く

メソッドデコレーターは：
- 3つ引数を取る
- descriptorが本体
- 関数を書き換えられる

## 定型文
```ts
function MethodDecorator(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
) {
  // ここに処理を書く
}
```

### 3つの引数の意味f
| 引数        | 何か                                   | 例                                   |
|-------------|----------------------------------------|--------------------------------------|
| target      | メソッドが属するオブジェクト（prototype） | User.prototype                       |
| propertyKey | メソッド名                             | "greet"                              |
| descriptor  | メソッドの中身（書き換え可能）           | { value: function greet(){} }        |


第一引数は、スタティックであればクラス・staticでなければプロトタイプ
第二引数、プロパティーキー・メソッド名
第三引数、裏設定

### 例
```ts
function LogMethod(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
) {
  console.log("メソッドにデコレータが付きました:", propertyKey);
}

// 呼び出す側
class User {
  @LogMethod
  greet() {
    console.log("Hello!");
  }
}
```

## descriptor が一番大事
- descriptor.value が メソッド本体
- つまり、**これを上書きすれば メソッドの動きを自由に変えられる**

## つまりメソッドデコレータは何ができる？
- メソッドの前後にログを挟む
- 権限チェックを挟む
- キャッシュする
- メソッドの動きを差し替える
- 引数のバリデーションを入れる
👉 全部 descriptor.value を書き換えるだけ

### 例：メソッドをラップしてログを出す
```ts
function LogMethod(target: any, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;

  descriptor.value = function (...args: any[]) {
    console.log(`[LOG] ${key} が呼ばれました`);
    return original.apply(this, args);
  };
}

// 使う側
// class User {
  @LogMethod
  greet() {
    console.log("Hello!");
  }
}

new User().greet();

// 出力
[LOG] greet が呼ばれました
Hello!
```

## プロパティディスクリプタとは？
- JavaScript が内部で持っている プロパティの設定情報 のこと

例：
```ts
const user = { name: "Alice" };

// 見える情報はこれだけ
name: "Alice"

// でも実はブラウザ内部では、name には 裏設定 がある
console.log(Object.getOwnPropertyDescriptor(user, "name"));

// 出てくるのはこういうやつ：
{
  value: "Alice",
  writable: true,
  enumerable: true,
  configurable: true
}
```
- プロトタイプではなく、ブラウザが裏で持っている情報になる

👉 これが **プロパティディスクリプタ**

### getOwnPropertyDescriptor とは？
- 「オブジェクトのプロパティにくっついている 裏設定（ディスクリプタ） を取り出すメソッド」

### 4つの裏設定の意味
| 設定         | 意味                         |
|--------------|------------------------------|
| value        | 実際の値（"Alice"）          |
| writable     | 値を書き換えられる？         |
| enumerable   | for...in で表示される？      |
| configurable | この設定自体を変更できる？   |

### たとえば writable を false にすると？
```ts
Object.defineProperty(user, "name", {
  writable: false
});

// すると
user.name = "Bob"; // 変更できない
```

### enumerable を false にすると？
```ts
Object.defineProperty(user, "name", {
  enumerable: false
});

// すると
for (const key in user) {
  console.log(key); // name が出てこない（ループに出ない）
}
```

### configurable を false にすると？
```ts
Object.defineProperty(user, "name", {
  configurable: false
});
```
すると：
- writable を変更できない
- enumerable を変更できない
- value を変更できない
- delete できない
👉 つまり ロックされる
- 一回falseにすると、trueにできない


## まとめ
- メソッドデコレータは「メソッドをラップする仕組み」
- descriptor.value がメソッド本体
- それを書き換えることで動きを変えられる
- target = prototype、propertyKey = メソッド名

```ts
function Deco(target: any, key: string, descriptor: PropertyDescriptor) {}
```

- プロパティディスクリプタ＝プロパティの裏設定
- value / writable / enumerable / configurable の4つ
- Object.defineProperty で変更できる
- メソッドデコレータは descriptor.value を書き換えて動きを変える
