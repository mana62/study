# パラメータデコレータ
パラメータデコレータは **「このメソッドの第◯引数にデコレータが付いている」という情報を取得**するための仕組み

- メソッドのパラメータにもデコレータを置くことができる
- 引数は3つ取れる

## 引数
- 第一引数：target = メソッドが属するオブジェクト（prototype）
- 第二引数： propertyKey = メソッド名
- 第三引数： パラメータが何番目に来ているか（number）

第一引数は、スタティックであればクラス・staticでなければプロトタイプ
第二引数、プロパティーキー・メソッド名
第三引数、パラメータが何番目に来ているか


## 例
```ts
function LogParameter(target: any, propertyKey: string, parameterIndex: number) {
  console.log("target:", target);
  console.log("propertyKey:", propertyKey);
  console.log("parameterIndex:", parameterIndex);
}

class User {
  greet(@LogParameter message: string, @LogParameter times: number) {
    console.log(message.repeat(times));
  }
}

// 実行結果（クラス定義時に出るログ）
target: User.prototype
propertyKey: greet
parameterIndex: 1
target: User.prototype
propertyKey: greet
parameterIndex: 0
```
❗️ ポイント：デコレータはメソッド実行時ではなく **「クラス定義時」に実行される**


### ① target
- インスタンスメソッド → prototype
- static メソッド → クラスそのもの

```ts
class User {
  greet() {}           // target = User.prototype
  static hello() {}    // target = User
}
```

### ② propertyKey
- デコレータが付いたメソッド名（string）

```ts
例："greet"
```

### ③ parameterIndex
- デコレータが付いた引数が何番目か（0始まり）

```ts
例：第1引数 → 0、第2引数 → 1
```

## 用途
- DI（依存性注入）
- 引数のバリデーション
- メタデータの収集（Reflect Metadata と併用）
- フレームワーク的なルーティング（NestJS がこれを使う）

## ⚠️ 注意点
### ① パラメータデコレータでは 引数の値は取れない
- よくある誤解：デコレータで引数の値をチェックできる？
→ できない
- デコレータは「クラス定義時」に実行されるため、メソッド実行時の値は存在しない

### ② descriptor（PropertyDescriptor）は渡されない
- メソッドデコレータと違い、パラメータデコレータでは descriptor を操作できない

つまり：
- メソッドを書き換える
- ラップする
- 実行前後に処理を挟む
→ 全部できない

### ③ 単体ではあまり役に立たない
- パラメータデコレータは メタ情報を集めるだけ なので、実際の処理はメソッドデコレータやクラスデコレータと組み合わせる必要がある

## まとめ
- パラメータデコレータは メソッドの第◯引数に付いたデコレータ を識別するための仕組み

引数は
- target：prototype または クラス
- propertyKey：メソッド名
- parameterIndex：引数の位置

- 値は取れない・descriptor はない
- メタ情報を集める用途が中心（メタ情報：コードそのものではなく、コードに付ける追加の情報）
