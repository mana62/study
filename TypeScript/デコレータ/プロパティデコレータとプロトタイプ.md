# プロパティデコレータとプロトタイプ
プロパティデコレータ = **クラスの「プロパティ（nameとかage）」が定義された瞬間に呼ばれる関数**
- プロパティの上に置く
- クラスデコレーたよりもプロパティでコレーたが先に実行される
- staticではない時の第一引数は、プロトタイプになる
- 何も返さない

## プロパティデコレータの引数は 2 つ
```ts
// 定型文
function Deco(target: any, key: string) {}
```
- target → prototype（インスタンスの設計図）
- key → プロパティ名

第一引数は、スタティックであればクラス・staticでなければプロトタイプ
第二引数、プロパティーキー・プロパティー名


## デコレーターの順番
```bash
① プロパティ
👉 データの定義（最初に必要）
② メソッド
👉 振る舞い（データの後）
③ アクセサ
👉 データ操作ルール
④ パラメータ
👉 外部入力
⑤ クラス完成
```

## クラスの組み立て
クラスは実はこういう組み立て作業
```bash
① 設計図を読む
② プロパティを登録
③ メソッドを登録
④ getter/setter登録
⑤ 最後にクラス完成
```

## なぜこの順番なのか？
### 理由①：存在が先に必要
👉 プロパティがないとメソッドが意味不明

### 理由②：上書きできるようにするため
👉 メソッドデコレーターで関数を書き換えるには
👉 先に元が必要

### 理由③：依存関係の都合
👉 getter/setterはプロパティに依存する

## まとめ
デコレーター順番＝これ
**データ → 機能 → ルール → 入力 → 完成**
