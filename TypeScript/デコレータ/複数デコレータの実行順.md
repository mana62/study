# 複数デコレータの実行順
ルール：
① ファクトリの呼び出し → 上 → 下
② デコレーターの実行 → 下 → 上

## シンプルデコレータ（下 → 上）
- 下 → 上 の順で実行される

```ts
@A
@B
class X {}

// 実行順
B → A
```

## デコレータファクトリ（引数など、上 → 下）
- 上 → 下 の順で実行される

```ts
@Component({ template: "..." })
@Logging
class X {}

// 実行順
Component → Logging
```

## なぜ違うの？
- シンプルデコレータ → 関数そのもの（デコレーターは「関数のネスト（入れ子）」だから下から実行される）
- デコレータファクトリ → 「関数を返す関数」なので、まず上から評価される

👉
ファクトリは「デコレーターを作ってるだけ」

👉
入れ子になるのは「作った後」







だけ

👉 順番が2つあるから混乱してるだけ

① 作る順番 → 上から
② 使う順番 → 下から
🔸 ① まず「デコレータファクトリ」を捨てて考える
@A
@B
class X {}

👉 これはこう👇

A(B(X))

👉 だから

B → A

👉 ここはOKですよね

🔸 ② 次にファクトリだけ見る
@A()
@B()

👉 これはただのこれ👇

A()
B()

👉 普通のJSなので

A → B（上から）
